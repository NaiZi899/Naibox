# NaiBox 使用说明

NaiBox 是一个本地 AI 网关：把多个上游账号池化，对外只暴露一个 OpenAI 兼容的
`base_url` 与一把 `api_key`。选号、冷却、重试、额度刷新、签到都由网关负责，
客户端只认 OpenAI 协议。

这份说明按「第一次用」的顺序写：装起来 → 打开控制台 → 接客户端 → 加账号 →
配出口 → 备份 → 排错。每一节末尾给出对应的配置键或端点，便于直接查。

## 1. 装起来

两种形态，同一套内核：

- **桌面版**（`NaiBox.exe`）：双击即用，起一个内嵌窗口指向本机控制台，托盘常驻。
- **服务端**（`Naibox-server-<goos>-<goarch>`）：Linux/macOS 上跑，适合放进 Docker 或 systemd。

启动参数（桌面版）：

- `-config <路径>`：指定配置文件，默认用数据根下的 `config.json`。
- `-data-dir <路径>`：指定数据根，默认 `%APPDATA%\NaiBox`。
- `-port <端口>`：覆盖监听端口（默认 7863；被占用会自动顺延）。
- `-console`：保留控制台窗口，便于看启动日志。

在 exe 同级放一个 `portable.flag` 文件，数据根就会落在 exe 目录（U 盘/绿色部署）。
服务端形态只认 `-config`，其余按配置走。

**第一次启动要先有配置文件。** 把发行包里的 `config.example.json` 复制成
`config.json`，改里面的 `api_key`（建议换成随机串）。没有这个文件时服务仍会以
默认值启动，但所有路径与开关都是默认值，不利于排错。

## 2. 打开控制台

浏览器打开 `http://127.0.0.1:7863/ui`。

从**本机**打开时网关会自动把 `api_key` 注入页面，不需要手填；从别的机器打开时
需要自己在顶栏粘一次 key。这也是「403 管理接口仅允许本机直连」的来源：
`/admin/*` 默认只接受回环地址，或带 `Authorization: Bearer <api_key>` /
`?token=<api_key>` 的请求。

控制台左侧的导航分组是：

- **通用**：仪表盘、API 管理、账号池、任务调度、请求日志、可用模型、对话测试、设置、关于软件、自定义上游。
- **运维**：备份、出口线路、浏览器档案。
- **每个上游一组**：猫猫旅行、成长计划等（由上游自己声明的能力位决定，没有该能力就不出现）。

## 3. 接客户端

任何支持 OpenAI 协议的客户端都能用：

- **Base URL**：`http://127.0.0.1:7863/v1`
- **API Key**：`config.json` 里的 `api_key`
- **模型**：`GET /v1/models` 拿到的名字。多上游部署时模型名带上游前缀（`workbuddy/…`），
  默认上游的模型名保持裸名，老客户端不用改。

最小验证：

```bash
curl -s http://127.0.0.1:7863/v1/models -H "Authorization: Bearer <api_key>"
curl -s http://127.0.0.1:7863/v1/chat/completions \
  -H "Authorization: Bearer <api_key>" -H "Content-Type: application/json" \
  -d '{"model":"<model>","messages":[{"role":"user","content":"hi"}],"stream":true}'
```

其它端点：`POST /v1/images/generations`（图片生成）、`GET /status`（账号池概览）、
`GET /healthz`（无鉴权存活探针）。

## 4. 加账号

三种入口，都在账号池页：

- **OAuth（推荐）**：点某个上游卡片上的「添加账号」，网关会用**无痕窗口**打开授权页，
  你登录后它自动回填凭证。无痕是为了避免「以为加了新号、实际把浏览器里已登录的老号
  又授权了一次」。
- **批量导入**：粘贴 JSON。支持嵌套形 `{"auth":{…},"account":{…}}`、扁平形，以及逐行文本；
  具体认哪些形状由上游自己决定。
- **从别的机器搬**：用下面的导出/导入往返。

**导出**（账号池右上角）：

- `CSV` / `TXT`：清单格式，含 uid、昵称、额度、状态、线路，**永远不含凭据**。
- `JSON（含凭据）`：等同账号口令，会先要你确认；单账号导出成一个文件，可直接丢回
  `auths/<上游>/`；多账号导出成 zip，内含逐账号文件与 `manifest.json`。
  导出的东西能被「批量导入」原样吃回去。

## 5. 账号池怎么工作

- 每次请求按**权重**选一个可用账号：额度、空闲时长、近期成功率一起算。
- 触发软限流（429）会进冷却，连续触发按 `cooldown.soft_rate` × 2 指数退避，
  封顶 `cooldown.soft_rate_max`。
- 余额耗尽进硬冷却，等到上游重置时点（默认次日 04:00，按上游策略）。
- 连续失败达到 `pool.breaker_threshold` 会熔断该账号一段时间。
- **风控命中（11140 一类）默认立即停手**：不换号重试。换号继续打会把标记扩散到整池，
  `pool.restricted_rotate_max` 留作现场排查用的回滚通道（默认 0）。
- 签到/保活是每 30 分钟一次的被动扫描，时点在「设置 → 日常调度」里改。

## 6. 出口线路（egress）

一条线路 = 上游眼里的一个出口身份（IP + 地区）。账号通过 `egressId` 引用它，
该账号的全部出站请求（聊天、余额、签到、上报）都走这条线。

- 配置在 `config.json` 的 `egress[]`，也可以在控制台「出口线路」页增删改。
- `max_accounts` 默认 1、上限 3：同一出口上的账号越多，「IP 复用」这条关联证据越硬。
- `realm` 是渠道约束（`cn` / `intl`），国内号挂海外出口会在启动期与保存时都被拦下。
- `probe_url` 填一个返回 IP 的端点（如 `https://api.ipify.org?format=json`）就能探活；
  探活结果缓存 10 分钟，也可以手动强制重探。
- **改完要重启**才对出站生效（线路在装配期被编译成独立的连接池），探活不受影响。

绑线路是在账号池每行的「线路」下拉里做的；绑一条不存在的线路会被拒绝并说明原因。

## 7. 备份

「备份」页管三件事：备到哪（通道）、什么时候备（整点）、留几份。

- 通道：`local`（数据根下的 `backups/`）、`s3`（任意 S3 兼容存储，endpoint 必须 https）、
  `openlist`（AList / OpenList 的 HTTP API）。
- 定时：`backup.enabled` + `backup.hours`（整点，空 = 只手动）。每通道保留 `backup.keep` 份，默认 10。
- 包里是 `config.json` + 全部上游的 `auths/` + `data/`，附 `manifest.json`（每个文件的 sha256）。
  **不含日志**：日志是诊断材料，不是资产。
- 包内含账号凭据，只送到你自己控制的存储。

**恢复是手工动作**：页面上只能「下载」，不能「恢复」。热恢复会覆盖正在运行的
`config.json` 与 `auths/`，那是不可回滚的操作——下载后停掉网关，替换文件，再启动。

## 8. 浏览器档案

**⚠ 这一节是整套配置里最容易被配坏的地方。不确定它在做什么，就不要设置。**

档案与指纹配错**不会报错**：浏览器照开、页面照跑，只是上游看到的「那台设备」和网关里
这个账号对不上，或者指纹参数被原版浏览器静默丢掉——两种都以「账号被风控」结账，
而你不知道自己动过什么。最安全的做法只有两条：`profile_mode` 保持 `temp`、
**指纹全部留空**（留空 = 不做伪装，用真机值）。

只想「加个号」的话，这一节完全用不上。

一份档案 = 一份独立的浏览器配置（cookie / localStorage 都在
`browser/<id>/` 目录里）。它解决的是「加号之后登录态留不下来」：
不建档案也能用，那时走默认的**一次性无痕**模式。

- **不是无痕窗口**：要让加号走档案，需要把「设置 → 登录」的 `login.profile_mode`
  从 `temp` 改成 `reuse`。
- 档案可以绑**具体账号**（uid）与**出口线路**：浏览器和网关里这个号走同一个出口，
  风控看到的画像才一致。绑 uid 时会自动把账号名记进标签。
- 「启动」会真的拉起本机浏览器（Edge / Chrome / Brave / Chromium），并回读调试端口。
  端口只监听回环，网关**不**提供 CDP 服务。
- 删除默认连目录一起删（那是几百 MB cookie）；想留着抢救就勾「删除时保留目录」。
- **指纹**：填了 GPU / canvas / platform / 屏幕宽度这些字段后，启动参数里会带上
  `--fingerprint-*`。这类开关只有 **fingerprint-chromium** 那种变体才认，原版
  Chrome/Edge 会静默忽略——所以要在「浏览器」里填变体的绝对路径，否则**保存时就会被拦下**。

## 9. 设置项

- **系统提示词**：三模式 `passthrough`（默认，不改写）/ `custom`（整段替换）/ `append`（追加）。
  改写会改变上游看到的渠道画像，代价由选择改写的人承担；降级期三种模式都会整段换成中性提示词。
- **超时**：`upstream.timeout_seconds`（短 RPC 总时长，默认 120）、
  `upstream.header_timeout_seconds`（聊天首字节前上限）、`upstream.idle_timeout_seconds`（流中空闲上限）。
- **请求体上限**：`server.max_body_mb`（默认 8）。超了直接回 413，不会静默截断。
- **日志**：请求日志保留天数在设置页改；签到历史另外一份。
- **会话粘性**：`session_sticky`（默认开，TTL 30 分钟）让同一个会话尽量落在同一个号上。

## 10. 出问题怎么查

| 现象 | 多半是 |
|---|---|
| 401 / `missing or invalid API key` | 客户端没带 key，或 key 与 `config.json` 的 `api_key` 不一致 |
| 403 / `管理接口仅允许本机直连` | 从别的机器打开了 `/admin/*`，需要带 `Authorization: Bearer <api_key>` |
| 413 | 请求体超过 `server.max_body_mb`（多图/长上下文最容易撞） |
| 429 | 账号在软冷却或额度用完；看 `/status` 的 `cool_kind` 与 `reason` |
| 504 | 上游流总时长超限，或首字节迟迟不来（见 `upstream.*_timeout_seconds`） |
| `所有账号不可用` | 该上游全部号都在冷却/熔断/被禁用；账号池页看每行的原因 |
| 11140 / 风控 | 默认立即停手；换出口、别换号继续打 |
| `/ui` 打不开或一直转圈 | 端口被占用导致顺延；看启动日志里的实际监听地址 |

日志在 `logs/`（桌面版托盘里有「打开当天日志」）。请求日志在控制台「请求日志」页，
按 uid / 模型 / 用量逐条可查。

## 11. 已知限制

- **不提供多租户计费**：一把或几把 key 共享整池，没有按用户计费与配额结算那层。
- **指纹要自备浏览器**：只支持带 `--fingerprint-*` 的变体，发行包不带 Chromium 变体。
- **指纹填错没有提示**：值本身不合理（比如 4000 宽的"手机"）会被范围校验挡住，
  但"看起来合理却与账号不搭"的组合（中美时区配国内号、Mac 平台配 Windows 出口）
  只能靠你自己判断——这类矛盾正是风控会抓的特征。
- **不提供远程 CDP**：档案只回读调试端口，不对外暴露控制通道。
- **备份不做自动恢复**：只下载，替换文件靠手工。
- **出口线路改动要重启**：探活可以当场验证，生效要等重启。

## 12. 安全提醒

这些文件等同账号口令，**不要进版本库、不要发群**：

- `config.json`（含 `api_key` 与上游密钥）
- `auths/`（每个上游一个子目录，里面是 access token / refresh token）
- `data/`（`state.json` 记着账号池运行态）
- `browser-profiles.json` 与 `browser/`（cookie 与最近访问的 URL）
- 导出的 `naibox-accounts-*` 与 `workbuddy-*.json`

仓库根的 `.gitignore` 已经挡住上面这些；如果你把数据根指到仓库里，务必确认这一条还生效。
